3 · Invarianti (AD-1…AD-9)

AD-1

Nessun runtime, zero metadati

Niente nuovo package; niente file di metadati per componente. Verità per-istanza in Penpot, profili per specie versionate.

AD-2 · eccezione AD-11

Conferma umana = unico gate

H1 allineamento+Penpot, H2 generazione. Un sì = un piano-diff numerato; i sì esecutivi non persistono. Garanzia convenzionale, non eseguibile.

AD-3

Base congelata

La fotografia dello stadio è l'unica base decisionale; rilettura = solo invalidazione. Mai cache o fixture.

AD-4

Profili versionati

JSON in packages/scripts/profiles/<nome>.json, campi name/version/headless/tokens. Default proposti, umano ratifica.

AD-5

Mani solo su hand-owned

Mai su @generated. Precedenza shadcn < extras < generato: extras solo additivo. Un token, un solo proprietario.

AD-6

Un solo vocabolario: Tailwind theme

Token → variabili @theme v4 per Puck. Mai struttura oltre gli organismi.

AD-7

Fedeltà = giudizio umano

Contratto 1 giudicato, mai score. Contratto 2 verificato a H2 contro lettura congelata. Riferimento card opzionale.

AD-8

Il gate ha un contenuto

4 controlli mostrati prima del sì: contratto esistente, ruoli ammessi, token nel vocabolario, nomi in convenzione.

AD-9

Livelli sequenziali

L0→L1→L2→L3; il successivo si apre solo a precedente completo. Deroghe solo esplicite e registrate.
